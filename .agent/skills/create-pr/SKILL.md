# PR を作成

適切な説明を含むプルリクエストを作成する。

## ブランチの整理

PR作成には2つのブランチが関係する：

| ブランチ | 説明 | 確認事項 |
| --- | --- | --- |
| **ソースブランチ** | 現在チェックアウトしているブランチ（PRの変更元） | リモートにpushされていること |
| **ベースブランチ** | マージ先のブランチ | リモートに存在すること |

### ベースブランチの決定

**指定された引数:** `$ARGUMENTS`

- 引数が指定されている場合: **その引数をベースブランチとして使用**
- 引数が空の場合: **develop をベースブランチとして使用**（このリポジトリのメインブランチは develop）

## 手順

### 1. ブランチの確認

- **ソースブランチ**: `git status` でtracking情報を確認し、現在のブランチがリモートにpushされているか確認する
- **ベースブランチ**: `git ls-remote --heads origin {ベースブランチ}` でリモートに存在するか確認する
- いずれかに問題がある場合は、開発者に対応を促して処理を中断する

### 2. 変更内容の分析

- `git log {ベースブランチ}..HEAD --oneline` でコミット履歴を確認する
- `git diff {ベースブランチ}...HEAD` で変更差分を確認する
- 変更の本質を理解し、適切なタイトルと説明を準備する

### 3. PRタイトルの作成

変更内容を端的に表す、明確で具体的な日本語タイトルを作成する。

例:
- 「ユーザー認証機能を追加」
- 「データベース接続タイムアウトの問題を修正」
- 「API レスポンスのパフォーマンスを改善」

「〜を追加」「〜を修正」「〜を改善」「〜を削除」などの形式で記述する。

### 4. PR本文の作成

[PRテンプレート](../../.github/PULL_REQUEST_TEMPLATE.md)を使用して本文を作成する。テンプレートの各セクションを以下の要領で埋める：

- **概要**: 変更全体を1〜2文で要約
- **変更点**: 具体的な変更内容を箇条書きで列挙
- **背景 / 目的**: なぜこの変更が必要なのかを説明
- **影響範囲**: 変更が影響するモジュールや機能を記載
- **スクリーンショット**: UI変更がある場合のみ記載（なければ「なし」）
- **関連issue / 補足など**: 関連するissue番号やレビューアへの補足
- **close #**: 関連issueがコミットメッセージやブランチ名から推測できる場合は記載、不明なら空欄のまま

### 5. PRの作成

`gh pr create` コマンドでPRを作成する。本文はHEREDOCを使って渡す：

```bash
gh pr create --base {ベースブランチ} --title "タイトル" --body "$(cat <<'EOF'
PR本文
EOF
)"
```

作成後、PRのURLを表示する。

## 注意事項

- ブランチの作成やコミットのpushは開発者が事前に行っているものとする。このスキルでは行わない。
- ベースブランチのデフォルトは **develop** である。main ではない。
